# 문제 6 설계 설명서 — 카페 주문 관리 프로그램

---

## 1. 프로그램 설명 및 사용법

### 초기 설정
- 잔고: `20000원`으로 시작
- 메뉴 6종 자동 등록 (커피 2, 라떼 2, 음식 2)

```
[커피] 아메리카노 - 2000원
[커피] 콜드브루   - 3000원
[라떼] 바닐라라떼 - 3500원
[라떼] 카페라떼   - 3000원
[음식] 쿠키       - 2500원
[음식] 샌드위치   - 7000원
```

### 메뉴 구성
| 번호 | 기능 | 설명 |
|------|------|------|
| 1 | 주문하기 | 메뉴 선택 후 수량 입력, 잔고에서 차감 |
| 2 | 잔액 조회 | 현재 남은 잔고 출력 |
| 3 | 주문 내역 조회 | 지금까지 주문한 내역 목록 출력 |
| 4 | 종료 | 프로그램 종료 |

### 주문 흐름
1. 메인 메뉴에서 `1. 주문하기` 선택
2. 메뉴 목록 출력 후 번호 입력 (`0` 입력 시 취소)
3. 수량 입력
4. 결제 성공 시 잔액 차감 및 주문 내역 저장

## 2. 클래스 구조 및 상속 관계

```
MenuItem (부모 클래스)
└── CafeItem (자식 클래스)

CafeManager (독립 클래스, CafeItem을 내부적으로 사용)
```

### MenuItem (부모 클래스, 추상 클래스)
- **멤버 변수 (protected)**: `name` (메뉴 이름), `price` (가격)
- **멤버 함수 (public)**: `get_name()`, `get_price()`, `set_price()`, `display()` (순수 가상)
- 공통 메뉴 정보를 추상화하는 기반 클래스. `display() = 0`으로 선언하여 단독 인스턴스화 불가
- `set_price()`는 0 이하 가격을 허용하지 않으며, 유효하지 않은 경우 int형 예외를 throw

### CafeItem (자식 클래스, MenuItem 상속)
- **추가 멤버 변수 (private)**: `category` (카테고리: 커피/음료/음식)
- **추가 멤버 함수 (public)**: `get_category()`, `display()` (override)
- 카페 메뉴에 특화된 정보(카테고리)를 확장하며, 부모의 순수 가상 함수 `display()`를 override하여 구체적 출력 구현

### CafeManager
- **멤버 변수 (private)**: `menu_list` (CafeItem 벡터), `balance` (잔액), `order_history` (주문 내역)
- **멤버 함수 (public)**: `add_menu()`, `print_menu()`, `order()`, `check_balance()`, `print_order_history()`
- 전체 카페 운영 로직을 캡슐화

## 3. 필수 활용 요소 적용 위치

아래 항목을 프로그램 내에서 모두 사용해야 한다. 어디에 어떻게 적용할지는 자유롭게 결정한다.
- 클래스 1개 이상 (멤버 변수 private, 멤버 함수 public) → [클래스 항목 참고](#클래스-멤버-변수-private-멤버-함수-public)
- 상속 관계 1개 이상 (부모-자식 클래스) → [상속 관계 항목 참고](#상속-관계)
- 조건문(if 또는 switch)과 반복문(for, while, do-while 중 택1 이상) → [조건문 + 반복문 항목 참고](#조건문--반복문)
- 명시적 형 변환 1회 이상 → [명시적 형 변환 항목 참고](#명시적-형-변환)
- try, catch, throw를 활용한 예외 처리 → [예외 처리 동작 상황 참고](#3-예외-처리-동작-상황)

### 클래스 (멤버 변수 private, 멤버 함수 public)
> 필수 활용 요소: 클래스 1개 이상 (멤버 변수 private, 멤버 함수 public)
- `MenuItem` 클래스: `name`, `price` → protected, `get_name()`, `get_price()`, `set_price()`, `display()` → public
- `CafeItem` 클래스: `category` → private, `get_category()`, `display()` → public
- `CafeManager` 클래스: `menu_list`, `balance`, `order_history` → private, 모든 조작 함수 → public

### 캡슐화
- `MenuItem::set_price()` (문제6.cpp 19행): price를 직접 변경하지 않고 setter를 통해서만 수정 가능. 0 이하 값 입력 시 int형 예외 throw로 외부 접근을 제어

### 추상화
- `MenuItem::display() = 0` (문제6.cpp 25행): 순수 가상 함수로 선언하여 MenuItem은 인터페이스 역할만 수행. 자식 클래스에서 반드시 구체 구현 필요

### 상속 관계
> 필수 활용 요소: 상속 관계 1개 이상 (부모-자식 클래스)
- `CafeItem : public MenuItem` (문제6.cpp 31행)
- `MenuItem`의 `name`, `price`를 상속받아 `category`를 추가 확장

### 다형성
- `CafeItem::display() override` (문제6.cpp 43행): 부모의 순수 가상 함수를 자식이 재정의. `print_menu()`에서 `menu_list[i].display()` 호출 시 CafeItem의 구현이 실행됨

### 조건문 + 반복문
> 필수 활용 요소: 조건문(if 또는 switch)과 반복문(for, while, do-while 중 택1 이상)
- **switch**: main 함수 157행 — 메인 메뉴 선택 처리 (1:주문, 2:잔액, 3:내역, 4:종료)
- **while**: main 함수 148행 — 종료 선택 전까지 반복 실행
- **for**: `print_menu()` 78행, `print_order_history()` 123행 — 목록 순회 출력
- **if**: `order()` 내 수량/잔액 검증, 메뉴 유효 범위 검사

### 명시적 형 변환
> 필수 활용 요소: 명시적 형 변환 1회 이상
- `order()` 93행: `float shortage = (float)(total_price - balance);`
  - int 연산 결과를 float형으로 명시적 형 변환하여 예외 throw
- `catch(float shortage)` 191행: `(int)shortage`
  - float 예외값을 출력 시 int로 형 변환

## 4. 예외 처리 동작 상황

### catch(int) — 수량 오류
> 필수 활용 요소: try, catch, throw를 활용한 예외 처리 — 주문 수량에 0 이하를 입력한 경우 throw 정수형(입력된 수량)
**발생 상황**: 주문 수량에 0 이하 값을 입력했을 때

```
수량: -1
수량 오류: -1은(는) 유효하지 않습니다.
```

- `order()` 66행: `if (quantity <= 0) throw quantity;` (int형으로 throw)
- `catch(int qty)` 86행: 입력된 수량을 메시지에 포함하여 출력

### catch(float) — 잔액 부족 오류
> 필수 활용 요소: 잔액이 부족하여 결제할 수 없는 경우 throw float형(부족 금액)
**발생 상황**: 총 결제 금액이 현재 잔액을 초과할 때

```
수량: 5
결제 오류: 5000원이 부족합니다.
```

- `order()` 72행: `throw (float)(total_price - balance);` (부족 금액을 float형으로 throw)
- `catch(float shortage)` 90행: 부족 금액을 int로 변환하여 출력

### catch(...) — 예상치 못한 오류
> 필수 활용 요소: 그 외 예상치 못한 예외 — catch(...)로 처리
**발생 상황**: int, float 외의 예외가 발생했을 때
- `catch(...)` 94행: "알 수 없는 오류가 발생했습니다." 출력
